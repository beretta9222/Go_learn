Интерфейсы:
    Интерфейсы представляют абстракцию поведения других типов. 
    Интерфейсы позволяют определять функции, которые не привязаны к конкретной реализации. То есть интерфейсы определяют некоторый функционал, но не реализуют его.

    type имя_интерфейса interface{
        определения_функций
    }
    Н: type vehicle interface{
            move()
        }

        type Vehicle interface{
            move()
        }
        
        func main() {
            
            var tesla Vehicle   // переменная интерфейса
            fmt.Println(tesla)  // nil
        }

    Реализация интерфейса

        type Vehicle interface{
            move()
        }
        
        // структура "Автомобиль"
        type Car struct{ }
        
        // структура "Самолет"
        type Aircraft struct{}
        
        
        func (c Car) move(){
            fmt.Println("Автомобиль едет")
        }
        func (a Aircraft) move(){
            fmt.Println("Самолет летит")
        }
        
        func main() {
            
            var tesla Vehicle = Car{}
            var boing Vehicle = Aircraft{}
            tesla.move()    // Автомобиль едет
            boing.move()    // Самолет летит
        }

    Полиморфизм
        Интерфейсы в языке Go позволяют реализовать концепцию полиморфизма - способность принимать многообразные формы:
        есть несколько типов, которые имеют одни и те же методы интерфейса, но по разному их реализуют. 
        То есть имеется один и тот же функционал и множество форм его реализации, и поведение интерфейса изменяется в соответствии с типом, который реализует интерфейс


        type Vehicle interface{
            move()
        }
        
        type Car struct{ model string}
        type Aircraft struct{ model string}
        
        
        func (c Car) move(){
            fmt.Println(c.model, "едет")
        }
        func (a Aircraft) move(){
            fmt.Println(a.model, "летит")
        }
        
        func main() {
            
            tesla := Car{"Tesla"}
            volvo := Car{"Volvo"}
            boeing := Aircraft{"Boeing"}
            
            vehicles := [...]Vehicle{tesla, volvo, boeing}
            for _, vehicle := range vehicles{
                vehicle.move()
            }
        }

Горутины:
    Горутины (goroutine) представляют параллельные операции, которые могут выполняться независимо от функции, в которой они запущены. Главная особенность горутин состоит в том, что они могут выполняться параллельно. 
    Для определения горутин применяется оператор go, который ставится перед вызовом функции:
        go вызов_функции

    Синхронизация горутин и WaitGroup
        Для упрощения синхронизации между горутинами в Go имеется пакет sync, который предоставляет ряд возможностей, в частности, структуру sync.WaitGroup
        WaitGroup — это структура, которая содержит счетчик количества горутин, завершения которых нам нужно дождаться. Он используется для ожидания завершения всех горутин. Для отслеживания всех горутин, которые вызываются в программе, WaitGroup предоставляет ряд методов:
            Add: сообщает, сколько горутин нужно дождаться.
            Done: вызывается при завершении горутины, чтобы указать, что ее выполнение завершено.
            Wait: используется основной горутиной, пока счетчик не станет равным нулю. Когда все горутины завершаются и счетчик становится равным нулю, функция Wait() возвращается и продолжает дальнейшее выполнение.

        var twg sync.WaitGroup
            twg.Add(5)
            for i := 0; i < 5; i++ {
                go func(ind int) {
                    defer twg.Done()
                    fmt.Println(ind)
                }(i)
            }
            twg.Wait()

    Мьютек:   
        Мьютексы позволяют разграничить доступ к некоторым общим ресурсам, гарантируя, что только одна горутина имеет к ним доступ в определенный момент времени. И пока одна горутина не освободит общий ресурс, другая горутина не может с ним работать.
        На уровне кода мьютекс представляет тип sync.Mutex, который определен в пакете sync. Для блокирования доступа к общему разделяемому ресурсу у мьютекса вызывается метод Lock(), а для разблокировки доступа - метод Unlock().
        
        RWMutex
            Горутина может только считывать данные, либо только изменять их. При выполнении операции записи совместное использование данных несколькими горутинами не допускается, тогда как при операции чтения несколько горутин могут считывать одни и те же данные без каких-либо проблем. Go предоставляет специальный мьютекс для чтения/записи - структуру sync.RWMutex, которая содержит различные поля для отслеживания доступа к памяти несколькими потоками. sync.RWMutex реализует несколько методов для блокировки/разблокировки:
                RLock(): используется для получения блокировки на чтение. Несколько читателей могут получить эту блокировку в одной программе. Блокировка на чтение не привязан к определенному потоку.
                RUnlock(): освобождает полученную одну блокировку на чтение.
                Lock(): блокирует мьютекс для записи. Доступен только для одного потока за раз. Если другой поток получает блокировку для целей чтения/записи, Lock блокируется до тех пор, пока блокировка не станет доступной для получения.
                Unlock(): снимает блокировку на запись. При выполнении Unlock без получения блокировки мы получим ошибку во время выполнения.
