Интерфейсы:
    Интерфейсы представляют абстракцию поведения других типов. 
    Интерфейсы позволяют определять функции, которые не привязаны к конкретной реализации. То есть интерфейсы определяют некоторый функционал, но не реализуют его.

    type имя_интерфейса interface{
        определения_функций
    }
    Н: type vehicle interface{
            move()
        }

        type Vehicle interface{
            move()
        }
        
        func main() {
            
            var tesla Vehicle   // переменная интерфейса
            fmt.Println(tesla)  // nil
        }

    Реализация интерфейса

        type Vehicle interface{
            move()
        }
        
        // структура "Автомобиль"
        type Car struct{ }
        
        // структура "Самолет"
        type Aircraft struct{}
        
        
        func (c Car) move(){
            fmt.Println("Автомобиль едет")
        }
        func (a Aircraft) move(){
            fmt.Println("Самолет летит")
        }
        
        func main() {
            
            var tesla Vehicle = Car{}
            var boing Vehicle = Aircraft{}
            tesla.move()    // Автомобиль едет
            boing.move()    // Самолет летит
        }

Полиморфизм
    Интерфейсы в языке Go позволяют реализовать концепцию полиморфизма - способность принимать многообразные формы:
    есть несколько типов, которые имеют одни и те же методы интерфейса, но по разному их реализуют. 
    То есть имеется один и тот же функционал и множество форм его реализации, и поведение интерфейса изменяется в соответствии с типом, который реализует интерфейс


        type Vehicle interface{
            move()
        }
        
        type Car struct{ model string}
        type Aircraft struct{ model string}
        
        
        func (c Car) move(){
            fmt.Println(c.model, "едет")
        }
        func (a Aircraft) move(){
            fmt.Println(a.model, "летит")
        }
        
        func main() {
            
            tesla := Car{"Tesla"}
            volvo := Car{"Volvo"}
            boeing := Aircraft{"Boeing"}
            
            vehicles := [...]Vehicle{tesla, volvo, boeing}
            for _, vehicle := range vehicles{
                vehicle.move()
            }
        }

Горутины:
    Горутины (**goroutine**) представляют параллельные операции, которые могут выполняться независимо от функции, в которой они запущены. 
    Главная особенность горутин состоит в том, что они могут выполняться параллельно. 
    Для определения горутин применяется оператор go, который ставится перед вызовом функции:
        `go вызов_функции`

Синхронизация горутин и **WaitGroup**
    Для упрощения синхронизации между горутинами в Go имеется пакет sync, который предоставляет ряд возможностей, в частности,
    структуру **sync.WaitGroup**.
    **WaitGroup** — это структура, которая содержит счетчик(количества горутин) завершения которых нам нужно дождаться. 
    Он используется для ожидания завершения всех горутин. Для отслеживания всех горутин, которые вызываются в программе, 
    **WaitGroup** предоставляет ряд методов:
        **Add**: сообщает, сколько горутин нужно дождаться.
        **Done**: вызывается при завершении горутины, чтобы указать, что ее выполнение завершено.
        **Wait**: используется основной горутиной, пока счетчик не станет равным нулю. Когда все горутины завершаются и счетчик
            становится равным нулю, функция **Wait()** возвращается и продолжает дальнейшее выполнение.

        var twg sync.WaitGroup
            twg.Add(5)
            for i := 0; i < 5; i++ {
                go func(ind int) {
                    defer twg.Done()
                    fmt.Println(ind)
                }(i)
            }
            twg.Wait()
Каналы:
Каналы (**channels**) представляют инструменты коммуникации между горутинами. 
Типы каналов:
    Небуферизированные Н: `Ch := make(chan int)` 
    Буферизированные Н: `Ch := make(chan int, 3)` 

Ограничения каналов:
    только для отправки Н: `var inCh chan <- int` | `make(chan <- int)`
    только для чтения Н: `var outCh <- chan int` | `make(<- chan int)`
    `chan тип_элемента`
        
Передача потоков данных
        Нередко одна горутина транслирует другой горутине через канал не одиночные значения, а некоторый поток данных. 
        В этом случае общий алгоритм состоит в том, что горутина-отправитель в течение некоторого периода отправляет данные. 
        Когда данные для отправки закончились, работа сделала, отправитель закрывает канал.
            
    for переменная := канал{
        //...........
    }

    Н:
        func main(){
            intCh := make(chan int) 
            go factorial(7, intCh)

            for { 
                    num, opened := <- intCh     // получаем данные из потока
                    if !opened { 
                        break    // если поток закрыт, выход из цикла
                    } 
                    fmt.Println(num)
            }
            или 
            for num := range intCh{
                fmt.Println(num)
            }


        }
        func factorial(n int, ch chan int){
            defer close(ch)
            result := 1
            for i := 1; i <= n; i++{
                result *= i
                ch <- result     // посылаем по числу
            }
        }

Каналы и конструкция **select**
    Ключевое слово **select** в Go используется для ожидания нескольких операций канала одновременно. 
    Оператор **select** похож на switch, который работает с несколькими выражениями case. В операторе **select** операторы case 
    применяются к операциям отправки/получения данных канала. **Select** выбирает определенный оператор case для выполнения операции.
                
        select{                    
            case операция_1:
                // обработка операции_1
            case операция_2:
                // обработка операции_2
        ..........................................
            case операция_N:
                // обработка операции_N
        }

Гонка данных:
    Гонка данных (**data race**) представляет ситуацию, когда два или несколько потоков одновременно обращаются к одному 
    и тому же участку памяти и выполняют по крайней мере одну операцию записи.
        
        H:
            var wg sync.WaitGroup 
            var value = 22

            func update_value(id int){
            
                fmt.Println("Goroutine", id, "starts")
                if(value==22){
                    time.Sleep(1*time.Second)
                    fmt.Println("Goroutine", id, "changes the value")
                    value += 1
                }            
                fmt.Println(value)
                wg.Done()     
            }
            
            func main(){            
                wg.Add(2)                  
                go update_value(1)
                go update_value(2)            
                wg.Wait()  
            }

        Проверка на гонку данных
            go run –race имя_программы || go build –race имя_программы
    
Мьютекс:
    Мьютексы позволяют разграничить доступ к некоторым общим ресурсам, гарантируя, что только одна горутина имеет к ним 
    доступ в определенный момент времени. И пока одна горутина не освободит общий ресурс, другая горутина не может с ним работать.
    На уровне кода мьютекс представляет тип **sync.Mutex**, который определен в пакете sync. Для блокирования доступа к общему
    разделяемому ресурсу у мьютекса вызывается метод **Lock()**, а для разблокировки доступа - метод **Unlock()**.
    **RWMutex**
        Горутина может только считывать данные, либо только изменять их. При выполнении операции записи совместное использование
        данных несколькими горутинами не допускается, тогда как при операции чтения несколько горутин могут считывать одни и 
        те же данные без каких-либо проблем. Go предоставляет специальный мьютекс для чтения/записи - структуру **sync.RWMutex**,
        которая содержит различные поля для отслеживания доступа к памяти несколькими потоками. **sync.RWMutex** реализует 
        несколько методов для блокировки/разблокировки:
            **RLock()**: используется для получения блокировки на чтение. Несколько читателей могут получить эту блокировку 
                в одной программе. Блокировка на чтение не привязан к определенному потоку.
            **RUnlock()**: освобождает полученную одну блокировку на чтение.
            **Lock()**: блокирует мьютекс для записи. Доступен только для одного потока за раз. Если другой поток получает
                блокировку для целей чтения/записи, **Lock** блокируется до тех пор, пока блокировка не станет доступной для получения.
            **Unlock()**: снимает блокировку на запись. При выполнении Unlock без получения блокировки мы получим ошибку во время выполнения.

Оператор **panic**:
    Оператор **panic** представляет еще один способ обработки ошибок. Он позволяет сгенерировать ошибку и выйти из программы. 
    Он используется для проверки непредвиденных ошибок во всей программе и чем-то похож на исключения в других языках 
    программирования. Всякий раз, когда в любой функции вызывается оператор **panic**, он останавливает выполнение этой функции 
    и завершает выполнение программы. Но если в функции, где произошла ошибка, вызывваются функции с операторм **defer**, 
    то перед завершением программы выполняются эти функции.
    В качестве параметра оператор **panic** принимает произвольное значение (формально интерфейс `interface {}`, 
    которому в реальности соответствует произвольное значение):
    `panic (interface {})`
